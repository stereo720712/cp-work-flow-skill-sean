# MR 描述 Markdown 模板

直接複製貼上到 GitLab MR 描述欄位。

---

```markdown
## 禪道任務

- 任務編號：#{任務編號}
- 任務標題：{任務標題}

---

## 改動摘要

{1~3 句話說明這個 MR 做了什麼，為什麼要做}

---

## 影響服務

| 服務 | 改動類型 | 說明 |
|---|---|---|
| {服務名稱} | 新增 / 修改 | {簡述改了什麼} |
| {服務名稱} | 新增 / 修改 | {簡述改了什麼} |

---

## 主要改動內容

- {改動點 1，例如：新增 XXX API，支援 YYY 功能}
- {改動點 2，例如：修改 ZZZ service，修正 AAA 問題}
- {改動點 3}

---

## 測試說明

- 自測報告：`{task_dir}/test-file-script/task-{任務編號}-self-test-report.html`
- 測試環境：dev
- 主要測試場景：
  - {場景 1}
  - {場景 2}

---

## Checklist

- [ ] 自測通過
- [ ] 無多餘的 debug log / 測試 code
- [ ] 金額計算使用 BigDecimal
- [ ] userId 來自 Token 解析，非前端傳入
- [ ] 新增 API 已確認 context-path 正確
- [ ] 資料庫變更已準備 SQL script（若有）
- [ ] Redis key 使用封裝方法（若有）
```

---

## 使用說明

- **改動摘要**：說人話，讓沒有背景的人也能快速理解這個 MR 的目的
- **影響服務**：只列有實際改動的服務，不要列沒動到的
- **主要改動內容**：條列最重要的 3~5 個改動點，不用列所有細節
- **Checklist**：根據實際情況勾選，沒有用到的項目可刪除
